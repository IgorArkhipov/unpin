# Unpin v0.6.1

`v0.6.1` makes project-scope discovery reflect the checkout selected for an
Unpin run. It prevents committed fixtures and inactive worktrees from appearing
as mutable project items while retaining discovery for the active checkout.

## Highlights

- Project-scope scans stop at inactive nested Git worktrees, regardless of
  where they are located beneath the selected checkout.
- Conventional `test`, `tests`, `fixture`, and `fixtures` subtrees are skipped.
- To inspect a different worktree, run Unpin with that worktree as
  `--project-root`; its own skills remain discoverable.

## Verification

- The release candidate must pass the full local provider matrix and live Pi
  and OpenCode host validation from the exact candidate commit, in addition to
  required CI and locked workspace checks.
- The release workflow verifies the GNU/Linux artifact's `GLIBC_2.35`-or-older
  symbol ceiling and runs `--version` and `--help` in Debian 12.
- Each archive has GitHub build provenance, a CycloneDX SBOM, and a
  workflow-generated `SHA256SUMS` trust root. Verify a downloaded archive with:

```sh
shasum -a 256 -c SHA256SUMS
gh attestation verify unpin-v0.6.1-x86_64-unknown-linux-gnu.tar.gz \
  --repo IgorArkhipov/unpin \
  --source-ref refs/tags/v0.6.1 \
  --signer-workflow IgorArkhipov/unpin/.github/workflows/release.yml
```
