# Unpin v1.4.3

`v1.4.3` standardizes Unpin development, CI, and release builds on Rust 1.98.0. It raises the minimum supported Rust version to 1.98 and retires builds with Rust 1.96 or 1.97 without changing Unpin's runtime behavior or public contracts.

## Highlights

- Development, CI, release, and Trunk configuration now select Rust 1.98.0 consistently.
- CI verifies the repository's Rust version surfaces stay aligned.
- Obsolete Rust 1.96 jobs are removed while every supported CLI and desktop release target remains in place.
- A small set of Clippy-driven source refactors keeps the Rust 1.98 build warning-free without changing behavior.

## Upgrading

This is an ordinary compatible patch update from `v1.4.2`. Prebuilt CLI and desktop users do not need Rust installed. Building Unpin from source now requires Rust 1.98 or newer.

CLI, terminal UI, desktop workbench, MCP protocol editions, provider paths, configuration formats, and the mutation safety model remain supported. On macOS, install `unpin` and `unpin-credential-broker` from the same verified archive. A compatible update preserves an already installed stable broker byte-for-byte, so this release does not require another Keychain authorization unless the broker is deliberately replaced or the signing certificate changes.

## Artifacts

The release provides three CLI archives and two native desktop archives:

- `unpin-v1.4.3-aarch64-apple-darwin.tar.gz`
- `unpin-v1.4.3-x86_64-apple-darwin.tar.gz`
- `unpin-v1.4.3-x86_64-unknown-linux-gnu.tar.gz`
- `unpin-desktop-v1.4.3-aarch64-apple-darwin.tar.gz`
- `unpin-desktop-v1.4.3-x86_64-apple-darwin.tar.gz`

Every archive has a CycloneDX SBOM, GitHub build-provenance and SBOM attestations, and an entry in `SHA256SUMS`. macOS artifacts retain the Unpin-specific signing identity and exact executable identifiers. See the [Gatekeeper and Control-click guide](../DESKTOP.md) and the [certificate-expiry runbook](../RELEASING.md#certificate-expiry-and-rotation).

## Verification

Publication remains blocked until the exact merged release commit passes the locked Rust workspace checks, macOS XCTest suite, live Pi and OpenCode validation, and finalized provider matrix. Published archives must pass checksum, attestation, archive-layout, version, architecture, signature, exact-identifier, designated-requirement, broker, bridge, Debian 12, and fixture-only MCP smoke verification.

Modern MCP proof includes stateless `2026-07-28` `server/discover` and `tools/list`; legacy `initialize` compatibility alone is not sufficient.

## Known limitations

- Rust 1.96 and 1.97 are no longer supported for source builds.
- Broker upgrades and certificate rotation are intentionally not automatic and require a separately verified manual migration.
- There is no Developer ID signing or notarization.
- Desktop support remains macOS-only and architecture-specific.
- crates.io, Homebrew, Linux ARM64, and Windows distribution remain deferred.
