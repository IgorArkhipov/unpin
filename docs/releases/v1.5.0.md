# Unpin v1.5.0

`v1.5.0` updates Unpin's inventory and controls for current Claude Code,
Codex, Cursor, Pi, and OpenCode configuration formats. It also includes the
September audit's dependency, desktop bridge, and large-inventory fixes.

## Highlights

- Claude Code skill overrides, plugin-bundled skills and hooks, and global
  hook-disable state are reflected in discovery. Codex matcher resets and
  Cursor's current global and portable plugin locations are handled correctly.
- Pi configured skills and optional package resources, plus OpenCode layered
  JSON/JSONC settings, configured skills, and tuple plugin references, are
  included in inventory and supported controls.
- Project-owned Pi and OpenCode configured skill paths cannot escape the
  selected project, including through symlinks. User-level external paths are
  read-only inventory. Configured scans are bounded, and warnings do not expose
  private paths.
- Desktop bridge requests now time out across both writes and reads. TUI and
  MCP inventory views avoid repeated work on large libraries. Dependency and
  CI action pins were refreshed, including replacements for a vulnerable and
  a yanked lockfile dependency.

## Upgrading

This is a compatible update from `v1.4.3`; no provider configuration migration
is required. The minimum Rust version remains 1.98 for source builds. The
existing plan, confirmation, backup, restore, and MCP no-write boundaries are
unchanged. On macOS, use the matching `unpin` and `unpin-credential-broker`
executables from a verified archive. A normal update must preserve the
installed stable broker; certificate or broker rotation still requires a
separately verified manual migration.

## Artifacts

The release retains three CLI archives and two native desktop archives:

- `unpin-v1.5.0-aarch64-apple-darwin.tar.gz`
- `unpin-v1.5.0-x86_64-apple-darwin.tar.gz`
- `unpin-v1.5.0-x86_64-unknown-linux-gnu.tar.gz`
- `unpin-desktop-v1.5.0-aarch64-apple-darwin.tar.gz`
- `unpin-desktop-v1.5.0-x86_64-apple-darwin.tar.gz`

Every archive must have a CycloneDX SBOM, GitHub build-provenance and SBOM
attestations, and a `SHA256SUMS` entry. Before publication, verify the exact
macOS signing fingerprint, executable identifiers, designated requirements,
and Hardened Runtime. The personal certificate is not Developer ID signing or
notarization; see the [Gatekeeper and Control-click guide](../DESKTOP.md) and
the [certificate-expiry runbook](../RELEASING.md#certificate-expiry-and-rotation).

## Verification

Publication requires the exact merged release commit to pass locked Rust
checks, macOS XCTest, live Pi and OpenCode validation, and a finalized provider
matrix. The draft's archives must pass checksum, attestation, layout, version,
architecture, signature, identifier, designated-requirement, broker, bridge,
Debian 12, and fixture-only MCP checks before the draft is published.

## Known limitations

- Native Zed host execution was not verified for this release candidate;
  fixture and local-matrix coverage confirms its existing skills and
  `context_servers` behavior. Zed plugins remain out of scope.
- Pi has no native MCP core; connector behavior belongs to package extensions.
- Pi v0.87.1 treats wildcard skill entries in top-level settings as filters
  over explicitly listed paths; wildcard-only entries do not expand into new
  paths. Unpin mirrors that loader behavior. If Pi settings exceed 512 filter
  rules or 64 KiB of rule text, affected configured skills become read-only
  inventory with a warning until the settings are simplified.
- macOS desktop distribution remains architecture-specific and is not
  Developer ID signed or notarized. crates.io, Homebrew, Linux ARM64, and
  Windows distribution remain deferred.
