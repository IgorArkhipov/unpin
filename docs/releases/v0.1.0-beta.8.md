# Unpin v0.1.0-beta.8

This MCP contract-correction release makes human-handoff tool descriptors
accurately distinguish internal Unpin app-state writes from provider
configuration changes.

## What changed

- `unpin_apply_toggle_item`, `unpin_apply_toggle_items`, and
  `unpin_plan_profile_provider` now report `readOnlyHint: false` because they
  persist transaction or payload metadata and coordination locks under Unpin's
  app-state root.
- The same tools report `destructiveHint: false` because they hand work off for
  human confirmation without changing provider configuration.
- Regression coverage verifies both the descriptor contract and byte-for-byte
  preservation of the target provider file during handoff.

MCP clients that cache `tools/list` responses should reconnect after upgrading
so they receive the corrected annotations and descriptions.

## Linux compatibility

The `x86_64-unknown-linux-gnu` archive remains built on Ubuntu 22.04 and
requires glibc 2.35 or newer. It runs on Debian 12 (glibc 2.36).

## Install

Download `unpin-v0.1.0-beta.8-x86_64-unknown-linux-gnu.tar.gz`, verify it
against `SHA256SUMS`, and verify build provenance:

```bash
gh attestation verify unpin-v0.1.0-beta.8-x86_64-unknown-linux-gnu.tar.gz \
  --repo IgorArkhipov/unpin
```

Extract the archive and place `unpin` on your `PATH`:

```bash
tar -xzf unpin-v0.1.0-beta.8-x86_64-unknown-linux-gnu.tar.gz
cd unpin-v0.1.0-beta.8-x86_64-unknown-linux-gnu
./unpin --version
./unpin --help
```

## Verification scope

Release validation covers the full fixture-backed and persistent provider
matrix, disposable-root Pi and OpenCode host validation, required CI, locked
package metadata, the version smoke, and the exact tagged artifact's checksum,
provenance, `GLIBC_2.35` symbol ceiling, and Debian 12 / Ubuntu 22.04 runtime
smoke.

## Beta limitations

- Windows is not supported.
- Strict live gateway attachment, native MCP-reference lifecycle, and native
  managed-hook activation remain unavailable where enforcement cannot be
  proven.
