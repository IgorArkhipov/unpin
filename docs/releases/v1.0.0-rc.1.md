# Unpin v1.0.0-rc.1

`v1.0.0-rc.1` is the first unified release candidate for the Unpin CLI,
terminal TUI, MCP server, and native macOS desktop workbench.

## Highlights

- The workbench organizes large inventories around Discover and Organize,
  Govern and Automate, Change Safely, and Recover and Audit.
- A bundled, version-matched `unpin` child remains the sole discovery,
  approval, mutation, backup, drift, audit, and restore authority.
- The bridge is local stdio only and exposes redacted typed state rather than
  provider payloads, private paths, secret keys, or MCP approval artifacts.
- CLI, TUI, and MCP compatibility remains intact; profiles, gateways, sessions,
  and hooks stay on those surfaces until later desktop parity phases.

## Desktop artifacts

The release provides separate archives for Apple Silicon and Intel macOS:

- `unpin-desktop-v1.0.0-rc.1-aarch64-apple-darwin.tar.gz`
- `unpin-desktop-v1.0.0-rc.1-x86_64-apple-darwin.tar.gz`

Each archive contains `UnpinDesktop.app`, its matching native `unpin` bridge,
the bridge-integrity manifest, README, and license. GitHub supplies build
provenance and CycloneDX SBOM attestations, and `SHA256SUMS` covers the complete
release asset set.

The app is ad-hoc signed with Hardened Runtime but is not Developer ID signed
or Apple-notarized. Gatekeeper can therefore require an explicit first-launch
override. Verify the checksum and GitHub attestation before using Finder's
Control-click **Open** flow. Do not disable Gatekeeper or strip quarantine
metadata. Full instructions are in the
[desktop guide](../DESKTOP.md).

Desktop updates are manual: verify the new archive, quit the old app, and
replace the app bundle. Uninstalling means moving `UnpinDesktop.app` to Trash;
shared CLI state and recovery evidence under `~/.config/unpin` are retained.

## Release-candidate verification

The candidate requires the full locked Rust workspace gates, the shared Xcode
test scheme, all release-tool tests, native arm64 and x86_64 desktop archive
smokes, live Pi/OpenCode host validation, and a finalized repository-local
provider-matrix evidence bundle from the exact candidate commit.

## Known limitations

- No Developer ID signing, notarization, or automatic updates.
- Desktop support is macOS-only and architecture-specific.
- `1.0.0` GA remains blocked on notarized desktop distribution and an
  installed-artifact smoke.
- crates.io, Homebrew, Linux ARM64, and Windows distribution remain deferred.
