# Unpin v0.1.0-beta.13

`v0.1.0-beta.13` makes backup recovery clearer and safer while reducing repeated
macOS Keychain prompts across concurrent MCP sessions.

## Highlights

- Restore Operations labels each backup with its provider, scope, affected
  item, requested state, and timestamp. The opaque identifier remains in the
  detail pane for precise recovery work.
- Every TUI control list keeps its selected row visible. Navigation uses the
  arrow keys, and the command footer uses consistent `Space` and `Enter`
  labels.
- `D` prepares deletion of a selected backup, `Enter` confirms the reviewed
  manifest, and `A` applies it. Deletion rechecks drift, rejects unsafe backup
  trees, and records audit evidence.
- macOS CLI/MCP processes share an idle-expiring credential broker over a
  private same-user Unix socket. The first successful start bundles the legacy
  purpose-separated keys into one Keychain item; later broker starts read that
  bundle once.

## Verification

- Required CI and locked metadata passed for the release candidate. A full
  beta.13 provider matrix was captured before the final release-only fixes;
  the maintainer approved its reuse, so it was not rerun on the tagged commit.
- The release workflow verifies the GNU/Linux artifact's `GLIBC_2.35`-or-older
  symbol ceiling and runs `--version` and `--help` in Debian 12.
- Each archive has GitHub build provenance, a CycloneDX SBOM, and a
  workflow-generated `SHA256SUMS` trust root. Verify a downloaded archive with:

```sh
shasum -a 256 -c SHA256SUMS
gh attestation verify unpin-v0.1.0-beta.13-x86_64-unknown-linux-gnu.tar.gz \
  --repo IgorArkhipov/unpin \
  --source-ref refs/tags/v0.1.0-beta.13 \
  --signer-workflow IgorArkhipov/unpin/.github/workflows/release.yml
```
