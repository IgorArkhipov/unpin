# Code Of Conduct

Unpin is a community project for people working around local AI-agent configuration. We want the project to be useful, respectful, and safe for contributors, maintainers, users, and reviewers.

This code of conduct is inspired by common open source community standards, including the Contributor Covenant, but is written for this repository's current public-readiness stage.

## Expected Behavior

Everyone participating in Unpin spaces is expected to:

- Be respectful, patient, and constructive.
- Welcome people with different backgrounds, experience levels, and viewpoints.
- Give feedback about code, design, documentation, and process without personal attacks.
- Accept responsibility for mistakes and correct course when asked.
- Keep discussion focused on what helps the project and its users.
- Be especially careful around privacy, local configuration, and security-sensitive details.

## Unacceptable Behavior

The following behavior is not acceptable:

- Harassment, intimidation, threats, stalking, or sustained disruption.
- Insults, slurs, demeaning comments, or personal attacks.
- Sexualized language, imagery, attention, or advances.
- Publishing private information without explicit permission.
- Discriminatory conduct related to identity, background, disability, nationality, race, religion, gender identity or expression, sexual orientation, age, body size, caste, class, or similar personal characteristics.
- Repeatedly pushing discussion after maintainers have asked for a pause or boundary.
- Any conduct that would reasonably be considered inappropriate in a professional open source setting.

## Scope

This code applies in project spaces, including GitHub issues, pull requests, discussions, code review, release notes, documentation, community chat if one is created, and any event or public channel where someone is representing Unpin.

## Reporting

For non-sensitive conduct concerns, open a GitHub issue in this repository and clearly mark it as a conduct report. Keep the report factual and include links, screenshots, or timestamps when useful.

Do not publish private personal information, secrets, or safety-sensitive details in a public issue. If a report needs private handling and no private reporting channel has been published yet, open a minimal GitHub issue asking maintainers to arrange private follow-up. Include only enough public detail for maintainers to understand that a private channel is needed.

Reports should be reviewed by maintainers promptly and fairly. Maintainers should respect the privacy and safety of reporters and affected people.

## Enforcement

Maintainers may take action when behavior violates this code of conduct or undermines a safe, constructive project environment. Possible actions include:

- Clarifying expectations in the thread where the behavior happened.
- Editing or deleting comments that violate this code.
- Closing, locking, or limiting participation in issues or pull requests.
- Giving a private or public warning.
- Temporarily or permanently restricting participation in the project.

Enforcement should be proportional to the behavior, the risk to participants, and any pattern of repeated conduct. Maintainers are expected to apply this code fairly and to hold themselves to at least the same standard as contributors.
